# Shingle size ablation (90% Jaccard threshold, SKILL.md only)

This file reports MinHash/LSH clustering of the SKILL.md corpus at the 90% Jaccard threshold with 2-gram, 3-gram and 4-gram word shingles, with precision and recall for each size. It reproduces Table 5 of the paper (`tab:shingle-ablation`, "Shingle size ablation at 90% Jaccard threshold.") and supports the sentence in Section 5.2 that introduces the table: "We repeated the MinHash analysis with 2-gram and 4-gram word shingles (Table 5)." The paragraph continues: "All three sizes found the same 351 hightower6eu files in clusters (99.7% of 352 in the corpus). Precision varies: 2-grams produce more topical false positives (P@>=10: 75.7% vs. 78.9%), while 4-grams fragment one campaign, dropping P@>=20 to 93.3%. The 3-gram default maximizes precision."

Generated by `shingle_ablation.py`. Run, with `LIBRARIAN_CORPUS` set, from the repository root: `python paper/sources/scans/shingle_ablation.py`. `LIBRARIAN_CORPUS` names the corpus snapshot and has no default; a run without it stops before computing anything. Output defaults to `shingle-ablation-<UTC date>.md` beside the script; set `SCAN_RESULTS_OUT` to a full path to write elsewhere.

The file list is the `file_index` of the committed scan `scan_20260314_threshold90_skillonly.json`, and paths resolve under `LIBRARIAN_CORPUS`. The shingling, MinHash parameters, LSH threshold, greedy clustering, and the precision and recall definitions are those Section 3.3 describes; only the shingle size varies between rows.

## Ground truth rules

**Recall.** Denominator: every file with a signature whose ClawHub archive path is `skills/hightower6eu/...`, read off the path (second segment of a path whose first segment is `skills`). Numerator: those of them in any cluster. This is a corpus-file count, not the 354 IOC slugs of Table 2, as the caption of Table 5 states.

**Precision.** A cluster of at least the stated size counts as a true positive if at least one of its files has a path-derived account in the 11 accounts of `clawhub_authors` in `paper/iocs.json` (anisafifi, hightower6eu, jordanprater, kenblive, moonshine-100rze, mupengi-bot, sakaen736jih, stveenli, thiagoruss0, timclawbot, zaycv). The list is read from iocs.json and asserted equal to the eleven accounts built into the script, which exits before running if the two disagree.

**Not file_level_precision.py's rule.** That script scores `strict` (Antiy CERT's 12 documented accounts) and `study` (the union of those with `clawhub_authors`, 18 accounts), and its `account_of` also requires the marketplace to be `clawhub-archive` and the path to have four segments. Neither set nor the gate is the rule Table 5 was computed with, so nothing is imported from it and this script applies its own rule.
